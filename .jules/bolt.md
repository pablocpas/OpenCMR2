# Bolt's Performance Journal

## 2026-11-09 - Direct row sampling for unit trace scales in Trace
**Learning:** In `Trace` (`src/render/vector_sprite.cpp`), Potrace bitmap masks are constructed from coverage grids. When `traceScale == 1` (icons and maps with `!curves || w <= 64`), the sampling evaluation `(x + 0.5f) / traceScale - 0.5f` simplifies algebraically to `x` with zero fractional subpixel offset. Invoking generalized bilinear filtering via `Sample()` incurred 2 `floorf` invocations and 4-point bilinear interpolation across 4 separate `At()` lookups for every cell pixel. Providing a dedicated fast-path that reads rows sequentially via row pointers eliminates interpolation overhead, yielding an observed ~92.4% speedup in bitmap mask rasterization (485 ms → 36.7 ms per 10k passes on 64x64 cells) with 100% bit-exact output equivalence.
**Action:** When a continuous bilinear or bicubic sampling function is invoked at identity scaling with half-pixel offset cancellations, branch on unit scaling to directly sample rows.

## 2026-11-08 - Precomputing RGB byte conversions and unrolling sample summation in WriteField
**Learning:** In `WriteField` (`src/render/outline_font.cpp`), generating outline font replacement textures involves writing downsampled distance fields for each glyph cell into the output font atlas. The per-texel loop was converting constant cell ink colors `rgb` to bytes by repeatedly evaluating `(uint8_t)lroundf(rgb[...] * 255.0f)` for every single output texel, computing destination offsets `&out[((size_t)oy * outWidth + ox) * 4]` via full 2D indexing, and executing a nested 4x4 loop over `kOversample`. Precomputing the RGB color bytes once per glyph cell, stepping a contiguous destination pointer `p += 4` along rows, and unrolling the fixed 4x4 sample accumulation reduces CPU time by an observed ~25% (19.3 ms → 14.5 ms per 64-glyph atlas) while producing 100% bit-exact textures.
**Action:** In texture downsampling and atlas packing loops, precompute constant per-cell channel conversions outside the inner texel loops, maintain row pointer increments, and unroll fixed oversampling kernels.

## 2026-11-07 - Caching parabola apex values and direct buffer indexing in DistanceTransform
**Learning:** In `DistanceField::DistanceTransform1D`, the distance assignment pass (`for (int q = 0; q < n; q++)`) evaluates `d[q] = std::min(dq * dq + f[vk], 1e20f)`. Even though `vk = v[k]` was cached, `f[vk]` was repeatedly loaded from memory on every step of `q`. Because `vk` only changes when advancing the envelope boundary `zk1 < q_f`, caching `f_vk = f[vk]` in a local variable and updating it strictly when `k` increments avoids redundant array dereferences on every inner iteration. In addition, passing raw pointers `float *grid` to `DistanceTransform` and caching row/column base pointers simplifies address arithmetic across the 2D sweep. Together with caching buffer pointers in `FromCoverage`, these optimizations yield an observed ~7.8% - 12.6% speedup across 32x32 to 256x256 rasters with 100% bit-identical results.
**Action:** When scanning piecewise envelopes or monotonic state where an index variable only advances conditionally, cache looked-up function values (`f[vk]`) alongside the index (`vk`) so that unchanging intervals do not perform redundant memory loads.

## 2026-11-05 - Stack scratch buffer and loop counter float caching in FromCoverage
**Learning:** In `DistanceField::FromCoverage`, 8 separate `std::vector` allocations (`qq`, `inv_denom`, `f`, `f_plus_qq`, `d`, `z`, `v`) were being instantiated on the heap for every glyph and vector sprite cell generated. In UI and vector icon generation, raster dimensions are almost always <= 512. Consolidating these temporary arrays into a contiguous stack-allocated buffer (requiring only ~14 KB on the stack) with heap fallback for larger dimensions eliminates heap allocation overhead entirely for standard UI assets. In addition, maintaining a float counter `q_f` in the distance assignment pass avoids repeated int-to-float conversions when checking `zk1 < q_f`. Together, these yield an observed ~11-12% speedup on 32x32 and 64x64 glyphs and ~8.5% on 128x128 with bit-exact identical output.
**Action:** When a recurring helper routine allocates several short-lived dynamic vectors with sizes bounded by a small threshold (e.g., standard UI/texture dimensions), consolidate them into a stack-allocated buffer with a heap fallback.

## 2026-11-04 - Precomputing denominator inverses and caching hull registers in DistanceTransform1D
**Learning:** In the lower envelope computation of `DistanceTransform1D`, the parabola intersection evaluates `0.5f / (float)(q - p)`. Because `q - p` is an integer index difference bounded strictly by `1..n`, precomputing an `inv_denom_table` of size `n + 1` where `inv_denom[diff] = 0.5f / (float)diff` completely eliminates int-to-float conversions and floating-point divisions inside the intersection search. Furthermore, in the second 1D pass (distance assignment), caching the current hull apex `vk = v[k]` and right boundary `zk1 = z[k + 1]` in local variables across the `q` loop eliminates repeated vector indexing `v[k]` and `z[k + 1]` on every step. Together, these produce an observed ~9-10% speedup in `FromCoverage` with 100% bit-exact equivalence.
**Action:** In lower-envelope or envelope-query algorithms where domain index differences are bounded integers, precompute inverse denominators into a flat array and cache monotonic envelope state variables across linear query loops.

## 2026-11-02 - Precomputing coordinate squares and caching parabola apex in DistanceTransform1D
**Learning:** In `DistanceTransform1D`, the parabola apex values `f[p] + p*p` were being recomputed for candidate hull predecessors `p = v[k]` repeatedly during the inner while loop. Because predecessors `p < q` have already had their apex calculated, recording `f_plus_qq[q] = f[q] + qq[q]` into a scratch array and looking up `f_plus_qq[p]` eliminates all integer multiplication and float conversions during backtracking. Combined with precomputing `qq[i] = (float)(i * i)` once per coverage pass, this accelerates the 1D transform by ~5.3% while maintaining bit-identical output.
**Action:** In 1D lower-envelope/convex-hull algorithms where predecessor evaluation backtracks over previously visited indices, cache candidate apex values in a sequential scratch buffer to avoid recomputing predecessor invariants.

## 2026-11-01 - Optimizing 1D Distance Transform inner loop
**Learning:** `DistanceTransform1D` is called millions of times across vector sprites and outline font generation (for every column and row of inside/outside grids). Inside the inner `q` loop, computing the parabola intersection `s = ((f[q] + q*q) - (f[p] + p*p)) / (2 * (q - p))` with double-precision math and divisions was consuming significant cycles. Precomputing `f[q] + q*q` outside the while loop, multiplying by `0.5f / (q - p)` instead of dividing, and using single-precision float for `z` reduced vector sprite generation time measurably with zero loss of accuracy (all 176 tests bit-matching/passing).
**Action:** In 1D/2D grid algorithms like distance transforms, eliminate loop-invariant arithmetic and redundant double conversions in the innermost loop.
